## Findings

### QA-001: mcp-validation.md says a dry run cannot show a refresh

- Severity: suggestion
- Related task / requirement: 1.3, 2.2
- Location: `docs/mcp-validation.md` (paragraph after the validation table, "A dry run on a fresh repository ... cannot show a refresh of previously installed text without a non-dry-run init"), at the reviewed identity
- Expected / actual: Expected an accurate description of dry-run capability. Actual: `init --dry-run` does show whether the owned block would be rewritten, because the plan lists a file only when its planned content differs from the file on disk (`InitializationPlan.Add`). Observed: a `CLAUDE.local.md` with the old-text owned block is listed as `Would update`, and the same file with the new-text block is not listed.
- Reproduction: Disposable clone with a seeded `CLAUDE.local.md` owned block (old vs new text), `worklog init --repository . --data-dir <disposable> --dry-run`.
- Evidence: Section "Checks and coverage", row "1.3 refresh preview, Claude Code".
- Recommended correction: Reword to state that a dry run on an already initialized (or seeded) repository lists the instruction files that would be rewritten but does not print the new text; the claim that a refresh cannot be previewed should be dropped or narrowed. Optionally record the disposable-seed method.
- Relationship: none

### QA-002: "rest of block unchanged" test is partly self-referential

- Severity: suggestion
- Related task / requirement: 1.1
- Location: `tests/WorkLog.Tests/Integration/InstructionOptionsTests.cs` lines 15-36 (`RenderedInstructionsShareSummaryGuidanceAndOtherwiseKeepPriorText`)
- Expected / actual: Task 1.1 asks to verify the rest of the block text is unchanged apart from the sentence. The test checks the restored block has 15 lines and contains three specific lines; the other 12 lines (and the long update-hint line) are not compared with the prior text, so an unintended edit to them would not fail the test. The claude-vs-codex equality check is also independent of baseline text.
- Reproduction: Edit any unasserted line of the block in `AgentInstructions.cs` (for example the "Multiple features..." line); the test still passes.
- Evidence: Source inspection of the test; I did not mutate the source (not in my write scope).
- Recommended correction: Assert the full restored block (or a stored hash/literal of the prior block) so that every other line is covered, if the maintainer wants the unchanged-text claim enforced by the test rather than by diff review.
- Relationship: none
