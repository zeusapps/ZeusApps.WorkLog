## Findings

### QA-001: The live wording check cannot authenticate in its isolated client homes, so acceptance 5.2 produced no output

- Severity: warning
- Related task / requirement: 5.1a, 5.2; design.md "Live check with both clients"
- Location: `tools/WorkLog.Smoke/SmokeProcessRunner.cs` (sets `CODEX_HOME` and `CLAUDE_CONFIG_DIR` to the disposable home) and `tools/WorkLog.Smoke/LiveWordingChecks.cs:26` (Codex runs first and its failure aborts the whole run), at 6d23796 plus working tree
- Expected / actual: Expected both clients to log one observation and handle the digest request so their summary and digest can be judged. Actual: Codex 0.165.0 with the isolated `CODEX_HOME` has no credentials and fails with HTTP 401 on every request (five reconnects on WebSocket, then five on HTTPS) before any tool call; the run throws and the Claude session never starts. The Claude isolated `CLAUDE_CONFIG_DIR` likely has the same problem (not probed, to avoid an extra billed call). Whether `--live-agents` has the same limitation was not checked.
- Reproduction: `dotnet run --project tools/WorkLog.Smoke -c Release --no-build -- --live-wording src/WorkLog/Bin/Release/net10.0/worklog.exe` (Release path as built); exit code 127 with `codex exited 1 ... 401 Unauthorized`
- Evidence: disposable log under `artifacts/smoke/<guid>/codex-*.log` (ignored by Git); output summarized above, no secrets involved
- Recommended correction: Decide how isolated live sessions obtain credentials without touching personal client configuration, for example an explicit API-key environment variable passed through for the child process, or a documented one-time login into the disposable home; then let each client run independently so one failure does not skip the other. The orchestrator or user must decide; QA did not copy personal credentials or rerun (only one session per client is authorized, and a retry would fail identically).
- Relationship: new
