## Findings

### QA-051: `DevInstallTests` preflight test fails when the newest build input is a directory

- Severity: warning (a failing full-suite run, not a digest defect)
- Related task / requirement: none in this change; regression of the full `dotnet test`
- Location: `tests/WorkLog.Tests/Updates/DevInstallTests.cs:41`; `tools/WorkLog.DevInstall/Staleness.cs` (`NewestSource`, `Walk`), at the reviewed identity
- Expected / actual: expected the full suite to pass (405 of 405, as the developer reported for D1). Actual: 1 failure, `Assert.Contains() Failure: Sub-string not found`, string "Source directory dashboard\\src changed af...", not found "Source file". The staleness check also counts a directory's own modification time. The newest build input in this working tree is the directory `dashboard/src`, touched when `app.daily.spec.ts` was last saved (spec files are excluded as files, but saving one moves the directory time). The test hard-codes "Source file" and so depends on which entry happens to be newest in the real checkout. Not caused by the digest change.
- Reproduction: `dotnet test -c Release --no-build --no-restore --filter "FullyQualifiedName~DevInstallTests"` in this working tree; the newest entry under `dashboard/src` by `ls --full-time` is the directory itself.
- Evidence: 1 failed, 404 passed (full run); 17 of 18 passed in the filtered `DevInstallTests` run; the directory timestamp is later than any non-spec file in `dashboard/src`.
- Recommended correction: let the test accept "Source file" or "Source directory" (assert on "changed after the package was built"), or make the fixture independent of the real checkout's timestamps. It will also reappear in CI-like runs whenever the last edit in `src` or `dashboard/src` was a spec file or a deletion.
- Relationship: pre-existing latent test fragility surfaced by this edit order; no earlier finding.
