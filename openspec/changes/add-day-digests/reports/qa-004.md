## Findings

### QA-071: The live digest evidence is attributed per client incorrectly and is asymmetric between Claude Code and Codex

- Severity: suggestion
- Related task / requirement: 5.2; Decision 6 (record whether the IDs matched)
- Location: `tools/WorkLog.Smoke/LiveAgentChecks.cs`, `ObserveAsync` (the `SELECT item, day, covers, text FROM digests` loop) and `Summarize`
- Expected / actual: The planned record needs, per client, the requested IDs, the saved IDs and the digest text. Actual: (1) both sessions share one `digests.db`, and the query is unfiltered and does not print `item`, so after the Claude session its section also prints Codex's stored digest labelled `claude:`. (2) `Summarize` prints `tool_use` inputs for Claude but never Claude's `tool_result` events, so the requested IDs (inside the `log_work` result) are only in the per-process log file; for Codex the raw `mcp_tool_call` item includes the result. The client with an empty or failed `save_digest` is hard to tell from the output alone. (3) A recognised event with an unexpected shape throws a non-`JsonException`, which aborts the whole mode after the first client.
- Reproduction: read the code; with a successful Codex session followed by a Claude session, the Claude section lists two `claude: stored digest` lines.
- Evidence: source inspection only (live sessions are excluded; no run).
- Recommended correction: filter the query by the client's ticket or change, print `item`, print `tool_result` text for Claude, and catch `Exception` (not just `JsonException`) per event. Do this before the rerun that the maintainer will do after sign-in, so the recording does not need manual correction.
- Relationship: new

### QA-072: Error and raw lines from the live sessions are printed unfiltered into output intended to be recorded

- Severity: suggestion
- Related task / requirement: 5.2; committable content hygiene
- Location: `tools/WorkLog.Smoke/LiveAgentChecks.cs`, the `raw:` branch of `Summarize` and the `NOT COMPLETED` line printing `result.Error`; `Program.cs` prints the absolute artifacts root
- Expected / actual: Output that will be pasted into `docs/mcp-validation.md` should not carry the home directory or account paths. Actual: raw stderr, unparsed lines and the artifacts root (an absolute path under the checkout) are printed as they are, so the recorder must redact manually. The current doc text is clean.
- Reproduction: read the code.
- Evidence: source inspection.
- Recommended correction: note the redaction step in the mode's comment or the doc, or print only a trimmed first line of stderr.
- Relationship: new
