## Findings

### QA-360: Stop acknowledgement is followed by immediate wrapper kill

- Severity: warning.
- Related task / requirement: C06 owned-host cleanup; ORCH-004 regression.
- Location: `scripts/c06-host-lifecycle.mjs:24-31` at reviewed identity `0d77685`.
- Expected / actual: After a healthy stop acknowledgement, cleanup should allow the owned wrapper to exit and the host to finish disposal, then force termination only if a bounded wait expires. The helper currently calls `killChild` immediately whenever the wrapper remains alive after `sendStop`, before its `waitChildExit` call. A returned `gracefulStopAcknowledged: true` therefore does not mean graceful termination was allowed to complete.
- Reproduction: Run the ignored controlled probe `node artifacts/realtime-dashboard-updates/reviews/qa-017/qa-017-probe.mjs`; the injected stop acknowledgement leaves the child alive and records `stop-ack -> kill -> wait-for-exit -> read-final`.
- Evidence: The no-host lifecycle spec covers startup-failure forced cleanup, but not a healthy wrapper that exits after a delay. The controlled probe confirms the forced kill happens before any exit wait. No real host was run, so host disposal consequences were not observed live.
- Recommended correction: After a successful stop acknowledgement, wait for wrapper exit for a bounded grace period and read/validate final disposal state; kill only if it does not exit within that period, then verify exit and port release.
- Relationship: New finding; related to ORCH-004, distinct from the corrected startup-failure ownership and forced-path assertions.
