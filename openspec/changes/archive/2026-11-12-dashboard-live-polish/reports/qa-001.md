## Findings

### QA-001: Page-level Retry has no pointer-focus guard and Space is untested

- Severity: suggestion
- Related task / requirement: 1.1, "Focus elsewhere is preserved"
- Location: dashboard/src/app.html (page Retry button in .live-status, no mousedown preventDefault); dashboard/src/app.live-status.spec.ts
- Expected / actual: the reader Retry has (mousedown)="$event.preventDefault()" so a pointer click never takes focus. The page Retry lacks it, so a pointer click focuses the button first and keepFocusOffRetry then moves focus to the header indicator. Pointer focus is not lost to the body, but a focused control elsewhere on the page (if a page-level draft or input exists) is blurred by the mousedown. The new unit tests for the draft case use button.click(), which does not simulate mousedown focus transfer, so they would not detect this. Whether any page-level draft exists was not verified.
- Reproduction: focus a page-level input, mousedown on page Retry, observe activeElement.
- Evidence: source inspection only.
- Recommended correction: if page-level drafts exist, add the same mousedown preventDefault; add a Space (keyup) activation case to the unit or e2e tests.
- Relationship: none
