## Findings

### QA-001: Today is rendered and copyable before the Ongoing inputs have loaded, and the Daily e2e scenarios fail intermittently against the packaged build

- Severity: warning
- Related task / requirement: task 3.1 (acceptance), task 2.2; requirements "Today and blockers", "Copy for daily"
- Location: `dashboard/src/app.ts` (`dailyTodayView` computed, around line 305, gated only by `activityReady()`; `loadOngoing` around line 805; `refreshData` around line 703); `dashboard/e2e/dashboard.spec.ts` lines 1349-1355 (`open` waits only for the first `daily-today-line`) and lines 1362-1370, 1421-1425
- Expected / actual: Today is derived from the board, which needs both the change activity and the 7-day ticket rows. Expected: Today and Copy for daily do not present or copy a partial board, and the acceptance run passes. Actual: `dailyTodayView` becomes non-null as soon as the change activity is loaded, while `loadOngoing` (timeline pages, then unlinked entries) is still in flight. In that window Today shows only change cards, without the ticket cards or the tickets of change cards, and Copy for daily copies that partial text (observed: `- daily-flow` instead of `- DEMO-2` and `- DEMO-3`; one title instead of two). The packaged e2e then fails in a full run: run 1 and run 2 failed "copies the plain-text block..." with that diff, run 3 failed "reordering two In-progress cards..." with `Received array: ["Daily flow"]`. The same scenarios pass when run alone or in small subsets, so the failures depend on timing. The developer record claims 36 of 36 on the packaged build.
- Reproduction: `./scripts/package.ps1 -OutputDirectory artifacts/<new folder>`; set `WORKLOG_DASHBOARD_EXECUTABLE` to the packaged `worklog.exe` and `WORKLOG_DASHBOARD_NO_NODE=true`; run `npm run test:e2e --prefix dashboard` and watch the "Daily view" scenarios (a failure appeared in 3 of 3 full runs, a different scenario in the third).
- Evidence: three full-run outputs (disposable, under `artifacts/qa-001-e2e-pkg-run*.txt`, not committed); failure screenshot showed a single "Daily flow" card in Today without tickets; an isolated live probe after a 1.5 s wait showed both cards with tickets ([desktop](../screenshots/qa-001-daily-desktop.png)).
- Recommended correction: gate Today and the Copy for daily action on the Ongoing inputs for the current selection having loaded (for example a loaded-scope signal beside `activityScope`, with the existing loading or empty treatment until then), and make the e2e `open` helper wait for that settled state (for example both expected Today titles) instead of the first line. Re-run the packaged e2e several times in full to show it is stable; the `--repeat-each` caveat in `docs/dashboard-validation.md` is a separate limitation. After the fix, update the validation record, which currently states 36 of 36.
- Relationship: new. The declared-store scenario failure on the Release build is the known QA-007 of `fix-dashboard-reliability` and is not part of this finding.
