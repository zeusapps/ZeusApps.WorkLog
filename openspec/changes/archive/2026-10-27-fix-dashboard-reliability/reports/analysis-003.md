## Findings

### ANALYSIS-061: The new loop test does not exercise the hop limit, and on Windows it also passes against the baseline

- Severity: suggestion
- Related task / requirement: 5.1, 5.2; the ANALYSIS-041 fix expectation ("fails closed on a loop"; regression coverage)
- Locations: `tests/WorkLog.Tests/Dashboard/DashboardReliabilityTests.cs:468-478` (`LinkLoopFailsClosedInsteadOfLooping`), `:426-466` (`LinkWhoseTargetHasALinkedParentCannotEscapeTheSource`); `src/WorkLog/Dashboard/SourcePath.cs:28` (hop counter)
- Observation:
  - **The loop test exercises the runtime, not the counter.** The test builds a direct loop a↔b with symbolic links. On Windows, the OS rejects that loop inside `ResolveLinkTarget`, and the baseline `Canonical` throws the same `IOException` (probe 7, measured). On Unix, .NET's own 40-link limit in `ResolveLinkTarget` throws for a direct loop (source reasoning, hypothesis). The test therefore does not reach the round-2 counter on either platform. The counter matters only for parent-component loops on Unix (p → q/r, q → p), where `readlink` fails with ELOOP and the restart walk would otherwise repeat forever (hypothesis). On Windows it matters for paths with more than 40 link components (probe 9b, measured).
  - **The test can pass without running.** It returns early when symbolic links cannot be created. That happens on Windows without Developer Mode or elevation, although the same loop can be built with junctions without any privilege. On this host it ran, because Developer Mode is on.
  - **No Windows test can catch a regression in the counter.** The linked-parent test also passes against the baseline on Windows (probe 2), as the validation doc states. CI runs only `windows-latest`. Removing or breaking the counter would therefore fail no test that CI runs.
- Proposed improvement and benefit: add one unprivileged Windows case that only the new code passes.
  - Hop counter: create a junction `n` → its own parent directory. Assert that `SourcePath.Canonical` of a path with 41 `n` components throws `IOException`, and that 40 components resolve. This is probe 9b; on this host it takes about 11 ms.
  - Linked-parent case: either make the target dangling (`hop` → `<box>/other/c/missing`, with `other/c` → outside), so that the existing test's "escapes" assertion fails against the baseline on Windows (probe 12c), or add that dangling case as a second assertion.
  - Optionally, build the loop test's links as junctions on Windows, as the neighboring tests do, so that it never returns early.
- Behavior-preservation risks: tests only.
- Evidence type: measured on Windows (probes 7, 9b, 12c against the verbatim baseline); hypothesis for Unix.
- Verification / measurement plan: run the new cases against the current build (they pass). Temporarily raise `MaxLinkHops` to a very large value, or revert to the baseline `Canonical`, and confirm that they fail.
- Relationship: new; test coverage of the ANALYSIS-041 fix. It does not block, because the counter's behavior was verified here by probe.
