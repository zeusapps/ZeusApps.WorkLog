## Assessment and limitations

- Root cause confirmed. After the second filter is submitted, the previous result set (two DEP-12 rows, each with a `.ticket-link`) stays in the DOM until the new query returns. `toHaveAttribute` on a locator that resolves to 2 elements raises a strict-mode violation immediately, and Playwright does not retry it. CI shows exactly this at the 4211 assertion. The local intermittence (3/40 originally, per the developer) is consistent with a race between the query response and the assertion.
- The fix is sound. `toHaveCount(1)` on the same locator is a multi-element-safe, auto-retrying assertion, so it waits (within the existing 15 s expect timeout) until the stale rows are replaced. No sleeps or raised timeouts. The attribute assertions are unchanged, so the same hrefs are still verified; the added count check slightly strengthens the test (exactly one link for 4211 and REC-5).
- Minor observation, no action needed: for REC-5 the previous result (4211) also has one link, so the second `toHaveCount(1)` can pass on stale content. That is still correct, because `toHaveAttribute` on a single stale element does not throw a strict violation; it retries until the href matches. The second guard is redundant but harmless. The later UNK-7 and DEP-30 steps follow the single-element pattern and are not exposed to the strict-mode throw.
- The 658 test ("keeps history available when a declared store cannot be resolved") fails deterministically here (the "Must not fallback" change is listed for the `store-member` fixture, whose `openspec/config.yaml` declares a nonexistent store) but passed in CI run 41685683969. The fix does not touch it and the fixture code is the same, so the difference is most likely local environment state, for example the locally installed OpenSpec CLI (1.13.1 here; the CI version was not checked) or a locally registered store. This is a hypothesis; I did not confirm the cause. It does not gate this fix, but it makes a local full-suite run stop at test 16 and hide the 24 later tests. I changed nothing to make it pass.
- Unexpected writes: none to the target. The working tree showed unrelated changes from other roles (findings.md modified, analysis-004.md untracked); I did not touch them. Test output went only to ignored directories (artifacts/dashboard-e2e, dashboard/test-results). All Playwright processes were harness-managed and ended; port 47831 was never used.
