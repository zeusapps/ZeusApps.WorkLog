## Findings

### QA-001: Packaged smoke tool rejects dev packages because it compares the whole `--version` output

- Severity: warning
- Related task / requirement: task 1.3 and design Decision 2 ("scripts that compare it keep working; those comparisons are updated to compare only the first token")
- Location: `tools/WorkLog.Smoke/UpdateAcceptanceChecks.cs:27`, `tools/WorkLog.Smoke/ClientRegistrationChecks.cs:21` (reviewed identity above); `tools/WorkLog.Smoke/UpdateAcceptanceChecks.cs:369` and `WorktreeAcceptanceChecks.cs:53` read the output but do not compare it
- Expected / actual: expected every in-repo consumer of `--version` to accept `0.3.9002 dev ...`. Actual: `Require(actual.Output.Trim() == selected.Current.Version, ...)` fails for any dev package, so the packaged update smoke cannot be run against a dev build. Deviation 7 changed `ReleasePackage` and `package-core.ps1` but not the Smoke tool.
- Reproduction: `dotnet run --project tools/WorkLog.Smoke -c Release --no-build -- --updates-only artifacts/qa-001/devpkg/worklog-0.3.9002-win-x64/worklog.exe` gives `Bootstrap launcher version mismatch.` The same command with the stable `0.3.0` package passes.
- Evidence: shell run above; no Smoke file is in the change's diff
- Recommended correction: compare only the first space-separated token in both places (or use a shared helper), and add a smoke run against a packaged dev build to the validation set.
- Relationship: none

### QA-002: Pre-existing personal data in `docs/mcp-validation.md`

- Severity: critical (role rule for any personal-data hit); pre-existing, not introduced by this change, so the orchestrator may triage it as non-blocking for the commit
- Related task / requirement: committable content hygiene; developer deviation 9
- Location: `docs/mcp-validation.md:67` and `:184` at the reviewed identity (baseline lines 67 and 145 hold the same text; `git show 8a7508e:docs/mcp-validation.md`)
- Expected / actual: expected no account or computer name in committable documents. Actual: two TRX result paths contain the account and computer name (category: account name and host name).
- Reproduction: search the file for the account and computer names. I do not repeat the values.
- Evidence: hits only in those two lines; the lines added by this change are clean.
- Recommended correction: replace the paths with a repository-relative placeholder in a separate cleanup, or accept as pre-existing.
- Relationship: pre-existing; ledger deviation 9

### QA-003: A first Preflight changes the modification time of the selected payload directory

- Severity: suggestion
- Related task / requirement: spec "Preflight SHALL be read-only toward the installation"
- Location: `tools/WorkLog.DevInstall/DevInstaller.cs` `Preflight` and the `InstallationLayout.ReadSelection` / `ReadPayload` calls it makes
- Expected / actual: expected no change to the installation. Actual: on a freshly copied stable installation the `LastWriteTime` of `versions/0.3.0` changed on the first Preflight (twice reproduced). File contents, names and the file list were identical, the second Preflight changed nothing, and hashing the same files with a plain `FileShare.Read|Delete` stream did not change the timestamp. I did not find the cause; it may be an environment effect (real-time scanning of the first-opened executable) rather than a write by the tool, and I cannot rule either out.
- Reproduction: copy `artifacts/qa-001/stable/worklog-0.3.0-win-x64` to a new folder, record directory `LastWriteTimeUtc` values, run `install-dev.ps1 -Action Preflight -Package <dev zip> -InstallationRoot ... -DataDirectory ... -Workspace ...`, compare.
- Evidence: content-hash snapshot unchanged; only the directory entry's time differs.
- Recommended correction: low priority. If the developer can reproduce it, find what touches the directory; otherwise note it as environmental.
- Relationship: none
