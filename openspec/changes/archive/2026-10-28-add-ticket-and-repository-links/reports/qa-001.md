## Findings

### QA-001: Markdown escaping helper is a no-op, so brackets in titles and ticket IDs stay live Markdown

- Severity: warning
- Related task / requirement: 3.1, Copy a work item as Markdown (copied text must describe recorded facts)
- Location: `dashboard/src/workitem-markdown.ts` line 29 (`escapeText`), used for the title, ticket link text, and repository label
- Expected / actual: `escapeText` is meant to backslash-escape `[` and `]`. The replacement string `"\$1"` is the two-character JavaScript string `$1` (`\$` is just `$`), so the replacement returns the match unchanged. A recorded title or ticket ID such as `a](https://other.example)` is copied as a live Markdown link, and the `### title` heading and link texts can render wrongly.
- Reproduction: `node -e 'const e=t=>t.replace(/([\[\]])/g,"\$1"); console.log(e("a [b] c"))'` prints `a [b] c` unchanged. No unit test in `workitem-markdown.spec.ts` covers brackets.
- Evidence: executed snippet above (output unchanged).
- Recommended correction: use `"\\$1"` (a backslash followed by the match), and add a unit test for a title, ticket ID and repository label containing `[`, `]`.
- Relationship: none
