## Findings

### QA-020: Batch read marking gives network-specific recovery guidance for missing documents

- Severity: warning
- Related task / requirement: 2.1 Accurate read-status outcomes; error-response heuristic; task 6.1 truthful recovery guidance
- Location: `dashboard/src/app.ts:1528` at implementation identity `11c3f4732c55`; the backend maps `FileNotFoundException` to HTTP 404 at `src/WorkLog/Dashboard/DashboardHost.cs:128`.
- Expected / actual: A failure without evidence of connectivity loss should be described neutrally or with recovery guidance matching its status. When a listed document has been deleted after the catalog snapshot, `/api/document` returns 404. `markChangeRead` classifies every status other than 409 and 401 as `failed`, then tells the user to retry after the dashboard connection is restored. That wrongly names a network outage as the cause and offers no refresh/reopen action for a missing document. Successful marks and retained drafts remain intact; 409 conflicts and 401 authorization loss have separate handling.
- Reproduction: Open a change from a disposable repository fixture, remove one document still listed in the selected catalog snapshot, then choose Mark change as read. Source inspection shows the document request receives 404 and flows through the generic failure summary. This specific batch-404 path was not executed during this review.
- Evidence: Source inspection only. `DashboardHost` maps `FileNotFoundException` to 404; `App.markChangeRead` routes all other non-409/non-401 errors to the failed count and fixed connection-restoration text. The 268 unit tests pass but do not cover this response.
- Recommended correction: Keep 409 as the only conflict outcome and 401 as authorization loss. Give 404 a missing/unavailable-document explanation with a refresh/reopen action, and keep network-specific retry language for network/5xx failures. Add a regression that verifies the 404 message while retaining prior successful marks and drafts.
- Relationship: New finding; distinct from ORCH-001–ORCH-010.
