## Findings

### QA-001: The unset case of the test launcher switch has no executed test

- Severity: suggestion
- Related task / requirement: 3.1 (switch "that the packaged build ignores unless set"); Local data access boundary
- Location: `src/WorkLog/Dashboard/EditorLauncher.cs` (`RecordingEditorLauncher.FromEnvironment`), `tests/WorkLog.Tests/Dashboard/ArchiveAndOpenTests.cs`
- Expected / actual: Expected an executed test that, with `WORKLOG_DASHBOARD_TEST_LAUNCH_LOG` unset or empty, `FromEnvironment()` yields the shell launcher, and with it set yields the recording launcher. Actual: tests inject a fake launcher and e2e always sets the variable, so the "inert unless set" claim rests on source inspection only. The code reads correctly (`Length: > 0`).
- Reproduction: search tests for `FromEnvironment`; no usage.
- Evidence: `grep` over `tests/` and `dashboard/e2e`, no hit.
- Recommended correction: add a small unit test of `FromEnvironment` (set, unset, empty), restoring the variable afterwards. Do not call the shell launcher.
- Relationship: none
