## Findings

### QA-011: A digest store that disappears while the server runs breaks `save_digest` until restart

- Severity: suggestion
- Related task / requirement: 1.1, 2.2; Decision 1; spec "Digest storage compatibility" (losing the store loses only digests)
- Location: `src/WorkLog/Persistence/DigestStore.cs` (`EnsureAvailable` caches `initialized`; `Save` calls `OpenReadWrite`, which recreates an empty file without the table)
- Expected / actual: Expected: losing `digests.db` costs only the stored digests, and the next save works or the process stops asking. Actual: after `digests.db` is deleted under a running server, every `save_digest` fails with `Digest could not be saved: SQLite Error 1: 'no such table: digests'`, and `log_work` keeps returning `digestRequest`, so each agent session keeps spending a turn on a request that cannot succeed. A restarted server recovers (it migrates the empty file).
- Reproduction: start `worklog serve` on a disposable data directory, log two observations for one ticket, `save_digest` (ok), delete `digests.db*`, call `save_digest` again.
- Evidence: packaged probe output `gone: save after delete -> ERR ... no such table: digests`; `log_work` after the delete still succeeded.
- Recommended correction: re-run the creation check when a write fails with a missing table (or check the schema on each save/request, which is cheap), and have `Request` stop issuing requests while the store is unusable.
- Relationship: none

### QA-012: The "no change and no ticket" rejection has no executed test

- Severity: suggestion
- Related task / requirement: 2.1, 2.2; spec "Digest request on logging" and "Saving a digest"; ledger scope decision 3
- Location: `tests/WorkLog.Tests/Mcp/DigestTests.cs` (`ChangeOnlyItemsGetRequestsAndLegacyUnlinkedEntriesDoNot`)
- Expected / actual: The test name promises that legacy unlinked entries get no request and are rejected by `save_digest`, but the body only logs two change-only entries and asserts a request. `log_work` rejects unlinked entries today, so only entries written by older releases are unlinked, and no test or smoke check covers them. The rule exists in `DigestService.Request` and `Save` and was reviewed only by inspection.
- Reproduction: read the test; none of the validation tests inserts an entry without change and ticket.
- Evidence: source inspection; probe confirmed `log_work` refuses unlinked input ("An OpenSpec change or qualified ticket reference is required.").
- Recommended correction: add a test that seeds an unlinked entry through the store or fixture (as `DashboardFixture` does for Daily) and asserts no request and a `save_digest` rejection; fix the test name or body.
- Relationship: none

### QA-016: `/api/daily` returns digests of every day for each shown item

- Severity: suggestion
- Related task / requirement: 4.1; Decision 4
- Location: `src/WorkLog/Persistence/DigestStore.cs` `Read` (filters by item only); `src/WorkLog/Dashboard/DailyService.cs` `Digests`
- Expected / actual: Only digests that can match a shown line are needed (those of the selected day and today). Actual: all stored digests for the items shown are returned and shipped with every Daily request, so a long-running ticket adds up to 280 characters per worked day to each response. - Reproduction: save digests for one item on many days, then call `POST /api/daily`.
- Evidence: source inspection only.
- Recommended correction: filter reads by the days shown, or by the covered entry IDs of the response, in `DigestStore.Read` or `DailyService`.
