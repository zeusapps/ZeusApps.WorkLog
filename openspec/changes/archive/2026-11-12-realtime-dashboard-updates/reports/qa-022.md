## Findings

### QA-480: Closure proof is not bound to the generation captured before the fault

- Severity: warning
- Related task / requirement: QA-440, duplicate ANALYSIS-460; tasks 1.1, 5.4, 7.2
- Location: `scripts/c06-disconnect-control.mjs:97-103` and `scripts/c06-fault-matrix.mjs:801-807` at reviewed identity `0d77685`
- Expected / actual: The disconnect record must prove that each exact A socket generation identified before fault injection closed on the browser side and both routed sides. `cycleDisconnect` captures IDs, but `requirePageClosed` resolves each label through the mutable `current` map and returns a snapshot of whatever generation is current at check time. The helper unit scenario does not exercise an overlapping replacement while the original generation is the required closure target. The live run did capture closed IDs `a2` and `a4`, but did not create a held replacement route (`heldReplacementRelease` was empty), so it does not cover the missing overlap case.
- Reproduction: In the helper, create an original generation for a label, then route a replacement while the original generation is still the required close target; inspect `requirePageClosed`. The function accepts only labels and checks the mutable current entry, not the previously captured generation identity.
- Evidence: The passing [single-disconnect diagnostic](../../../../artifacts/realtime-dashboard-updates/fault-matrix/2026-11-09T16-30-45-781Z-e66b5004.json) proves the ordinary path. The helper source and unit check reveal the untested generation-switch case.
- Recommended correction: Pass the captured generation IDs into the close assertion and verify page, client-route, and server-route closure on those exact generation objects; add a helper case that introduces a held replacement before checking the original close.
- Relationship: New regression finding under the assigned QA-440 recheck; related to canonical QA-440 and duplicate ANALYSIS-460.

### QA-481: Accepted handshake evidence is not correlated with a released replacement generation

- Severity: warning
- Related task / requirement: QA-440, duplicate ANALYSIS-460; tasks 1.1, 5.4, 7.2
- Location: `scripts/c06-fault-matrix.mjs:645-647` and `scripts/c06-fault-matrix.mjs:790-843` at reviewed identity `0d77685`
- Expected / actual: Each A page needs a recorded accepted SignalR handshake after outage release, tied to that page's new socket generation, before visible recovery is accepted. The helper starts its accepted-event index before fault injection and later selects any handshake in that slice; it does not assert event time is after release or associate the handshake with the newly reopened generation ID. The run has new socket IDs and successful reconciliation, but its record does not prove the handshake-generation/time relationship.
- Reproduction: Inspect `measureConnectedAt` and its call sites in `cycleDisconnect`: its predicate filters only by event kind after a pre-fault array index. No release timestamp or socket-generation identity is passed to the handshake predicate.
- Evidence: Source inspection at the frozen identity; the diagnostic raw record confirms successful ordinary recovery but no release-correlated handshake evidence.
- Recommended correction: Record the release monotonic timestamp and correlate each accepted handshake with the exact newly opened A generation; require both handshake timestamps to be after release before passing the cycle.
- Relationship: New regression finding under the assigned QA-440 recheck; related to canonical QA-440 and duplicate ANALYSIS-460.
