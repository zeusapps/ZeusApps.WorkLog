## Findings

### QA-080: Recovery gate is overwritten with wall-clock duration

- Severity: warning.
- Related task / requirement: 7.2, five-second recovery acceptance gate.
- Location: `scripts/c06-fault-matrix.mjs:866–872` at the reviewed identity.
- Expected / actual: The acceptance result and five-second check should use monotonic elapsed time. `assertCycleState` computes monotonic recovery duration at lines 654–657 and stores it; the end-of-cycle code overwrites that value using `Date.parse(reconciledAtUtc) - Date.parse(transportReestablishedAtUtc)` and gates on the wall-clock delta. A system clock adjustment during recovery can therefore distort or reverse the measured duration and cause a false pass or fail.
- Reproduction: Inspect the two assignments at lines 867 and 871 after `assertCycleState`; they replace the `performance.now()` based values already stored on the cycle record.
- Evidence: Static source evidence at `scripts/c06-fault-matrix.mjs:654–659,866–872`; no matrix run was performed.
- Recommended correction: Preserve the monotonic recovery duration as the gate and reported numeric metric; retain UTC timestamps only for human-readable chronology.
- Relationship: None.

- Severity: warning.
- Related task / requirement: 7.5 and the architecture documentation requirement for current live-update behavior.
- Location: `docs/architecture.md:57` at the reviewed identity.
