## Findings

### QA-180: Catalog revision is marked clean before watcher rebind completes

- Severity: warning.
- Related task / requirement: 2.1, 2.4 and 7.4; restored source roots must be rebound before the corresponding reconciliation is reported settled.
- Location: `src/WorkLog/Dashboard/DashboardLiveCoordinator.cs:464–471`; reproduced by `tests/WorkLog.Tests/Dashboard/DashboardLiveCoordinatorTests.cs:343–346` at the reviewed identity.
- Expected / actual: The catalog/document revisions should not be published clean until watcher rebinding for the discovered roots completes. The current code updates `catalogStamp`/`documentsStamp`, advances revisions, and clears both dirty bits under `stateGate`, then awaits `RebindWatchersAsync`. The full-suite test observes the advanced document revision and empty dirty set before the restored `demo` child root is present, then fails its root assertion. The old nearest-existing `openspec` parent remains in the root list; this run did not demonstrate a lost file update.
- Reproduction: In the supplied full-suite run, `MissingChangeRootIsWatchedAtItsNearestExistingParentAndReboundWhenRestored` restored `openspec/changes/demo/design.md`, emitted a directory hint against the nearest existing parent, waited only for document revision advancement plus `Dirty.Length == 0`, then asserted that the `demo` watcher root existed. The assertion failed at line 345 with only the data root and `openspec` parent present.
- Evidence: `DEV-015-016-full.trx` reports this one failed test; the test frame points to line 345. Source order at `DashboardLiveCoordinator.cs:464–471` commits the clean revision before awaiting root rebind.
- Recommended correction: Complete settings refresh and watcher rebinding before committing the new stamps/revisions and clearing dirty state; if rebinding fails, retain the relevant domains pending.
- Relationship: New QA regression finding; no prior finding covers clean-before-rebind ordering.
