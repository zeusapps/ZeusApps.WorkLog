## Findings

### QA-320: Forced-cleanup regression reuses an already exited child

- Severity: warning.
- Related task / requirement: tasks 1.1 and 7.2; ORCH-004 owned cleanup evidence.
- Location: `scripts/c06-host-lifecycle.spec.mjs:37–48`.
- Expected / actual: The forced-cleanup test should exercise killing a still-running invocation-owned wrapper and prove its exit plus port release. It reuses the child stopped in the earlier graceful case; that child already has `exitCode === 0`, so the helper skips `killChild` and line 48 fails.
- Reproduction: `node scripts/c06-host-lifecycle.spec.mjs` exits 1 with `AssertionError` at line 48 (`false !== true`).
- Evidence: Independent execution of the current frozen regression script; the production cleanup helper's `childHasExited` guard skips kill for an exited child.
- Recommended correction: Use a fresh running fake child for the forced branch, assert the kill and observed exit for that child, and retain the independent port-release assertion. Then execute the bounded failed-readiness cleanup path to establish invocation-owned process and port cleanup.
- Relationship: Rechecks ORCH-004; current failure blocks the required forced-cleanup regression evidence.

### QA-321: MCP case outcome reads signal and timeout from the global process

- Severity: warning.
- Related task / requirement: task 7.3; ORCH-006 truthful MCP compatibility outcomes.
- Location: `scripts/c06-mcp-compat.mjs:91–92`.
- Expected / actual: Each case's signal and timeout fields should describe its `spawnSync` result. The function captures that result as `childResult` but instead reads `process.signal` and `process.error`, which are unrelated global properties and leave those case fields null/false even when the child is signaled or times out.
- Reproduction: Source inspection of `runOwned`: `childResult.signal` and `childResult.error` are correctly used in the cleanup list, while the returned case object reads the global at lines 91–92. The preserved successful result does not trigger this unhappy path: all twelve recorded wrappers exited 0.
- Evidence: Existing raw MCP run at `artifacts/realtime-dashboard-updates/mcp-compat/2026-11-09T08-52-11-830Z-839b460f.json` passes its four success cases; it cannot establish accurate signal/timeout reporting for unsuccessful case results.
- Recommended correction: Populate per-case `signal` and `timedOut` from `childResult`, and add a bounded result-mapping probe for nonzero exit, signal and timeout so cleanup metadata remains truthful.
- Relationship: Rechecks ORCH-006; the startup shadowing exception is fixed, but failure metadata remains inaccurate.
